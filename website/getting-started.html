Getting started

This page covers both how to get started as a user (your administrator has invited you) and how to deploy a server yourself.

As a user

You need:

  • An enrollment token from your administrator
  • KeePassXC installed (the desktop client uses its keepassxc-cli to read and merge .kdbx files)
  • A pre-built binary for Linux, macOS or Windows — or Go 1.26+ if you prefer to build it yourself

On a phone you don't need any of the above — just install the Android app (see On Android below).

The desktop app, if you would rather not use a terminal

Everything below can be done in a window instead. The desktop app is a thin shell around the same command-line client — it owns no encryption, no server logic and no configuration of its own, it just runs the client for you and shows the result. Anything you do in one is visible in the other.

On Windows, take KeePass-Delta-Sync-Setup-<version>.exe from the releases page. It installs both programs into the same folder, which is what lets the app find the client without any PATH setup, and it installs for your user only — no administrator prompt. On Linux take the .tar.xz from the same page; on macOS build it with make package-darwin, since a signed .app needs a Mac to build on.

The first time you start it, a wizard asks for the server address and your enrollment token, then for a name and a file for your .kdbx — the same two steps as enroll and init below. After that you get a dashboard with tabs for Databases, Devices, Activity, Log, Administration and Settings, so you can sync one database or all of them, watch what the client is doing, and switch the interface between Danish and English.

Under Settings there is also autostart, which asks your operating system to run keepass-deltasync daemon when you log in — a logon task in Task Scheduler on Windows, launchd on macOS, systemd --user on Linux. It is set up entirely inside your own user account, so it needs no administrator either, and background sync then keeps running whether or not the app is open.

Steps

  1. Build the client 
    git clone https://gitlab.com/Star95/keepass-deltasync.git
cd keepass-deltasync/client
go build -o keepass-deltasync ./cmd/keepass-deltasync
    Put keepass-deltasync on your PATH or invoke it directly with ./keepass-deltasync.
  2. Enroll your device with the one-time token from your admin: 
    ./keepass-deltasync enroll --server https://deltasync.example.com <your-token>
    The client generates an X25519 keypair locally and sends the public part to the server. The private part stays on your device.
  3. Bind a local .kdbx file: 
    ./keepass-deltasync init mypasswords ~/keepass/my.kdbx
    Or, if you already have the same database synced on another device: 
    ./keepass-deltasync databases   # find the UUID of the existing one
./keepass-deltasync init mypasswords ~/keepass/my.kdbx --bind <UUID>
  4. Sync: 
    ./keepass-deltasync sync mypasswords
    You will be prompted for your master password. The client runs Argon2id locally (~200 ms) and syncs.
  5. Let the daemon run in the background for automatic sync: 
    ./keepass-deltasync daemon --store-keyring
    The first time, it prompts for your password and stores it in the OS keyring (Windows Credential Manager / macOS Keychain / libsecret). Subsequent starts are fully non-interactive.

Run the daemon automatically at login

Once the daemon works when you run it by hand, you can have your computer start it for you at every login, so syncing "just happens". Run the manual --store-keyring command first (step 5 above) and enter your master password once — autostart depends on the password already being saved in the OS keyring, because nobody is there to type it at boot.

Windows

The simplest reliable approach is a tiny launcher that starts the daemon hidden (no black console window), placed in your Startup folder.

  1. Next to keepass-deltasync.exe, create a text file named start-daemon-hidden.vbs with this content (change the folder path to where your .exe actually lives): 
    Set sh = CreateObject("WScript.Shell")
sh.CurrentDirectory = "C:\Tools\keepass-deltasync"
sh.Run "keepass-deltasync.exe daemon", 0, False
    The 0 means "run hidden".
  2. Press Windows+R, type shell:startup, and press Enter. Windows opens your personal Startup folder.
  3. Right-click start-daemon-hidden.vbs → Copy, then right-click inside the Startup folder → Paste shortcut. That's it — the daemon now starts hidden every time you log in.

Optional — Task Scheduler (more robust: it can restart the daemon if it ever crashes). Open Task Scheduler → Create Task…, add a trigger "At log on", and an action "Start a program" with program wscript.exe and argument the full path to your .vbs file. Choose "Run only when user is logged on" — that is required so the task can read your password from Windows Credential Manager. The same as a one-liner in PowerShell:

schtasks /create /tn "KeePass DeltaSync" /sc onlogon /rl limited /f /tr "wscript.exe \"C:\Tools\keepass-deltasync\start-daemon-hidden.vbs\""

Linux

Use a systemd user service. Create the file ~/.config/systemd/user/keepass-deltasync.service:

[Unit]
Description=KeePass DeltaSync daemon
After=graphical-session.target

[Service]
ExecStart=%h/.local/bin/keepass-deltasync daemon
Restart=on-failure

[Install]
WantedBy=default.target

Change the ExecStart path to wherever you put the binary. Then enable and start it:

systemctl --user daemon-reload
systemctl --user enable --now keepass-deltasync.service
systemctl --user status keepass-deltasync.service   # confirm it is running

View its log output any time with:

journalctl --user -u keepass-deltasync -f
Keyring note (Linux): the daemon reads your saved password from the desktop secret service (GNOME Keyring / KWallet, via libsecret), which is unlocked when you log in to your graphical desktop — so the service starts cleanly in a normal desktop session. On a headless server with no unlocked keyring, the keyring lookup will fail; there, run the daemon with --password-stdin reading from a protected file instead. If you want the service to keep running after you log out, enable lingering: loginctl enable-linger $USER.

On Android

The Android app is a sync service: it has no built-in entry editor. It keeps your .kdbx file in sync in the background, and you read and edit your passwords in your usual Android KeePass app — Keepass2Android or KeePassDX, both of which open the same file.

  1. Install the app. The quickest route today is Obtainium, which installs the signed APK straight from GitHub Releases and keeps it up to date. Point it at that repository, filter release titles by ^DeltaSync Android and extract the version with [0-9.]+$ — the same repository publishes desktop releases, and the two filters keep them apart. F-Droid took the app into its catalogue on 10 September 2026, so that channel is on its way; the builds are reproducible and carry the same signature, so you can move between the two without uninstalling.
  2. Enroll the device on the main screen. Tap Scan QR code and point the camera at the code shown in the admin panel, or type the server URL and the one-time enrollment token in by hand. The app generates an X25519 keypair and stores the device token in the Android Keystore. A server reached over plain HTTP works too, for one that only answers on your own network.
  3. Pick your .kdbx via the system file picker and match it to the database on the server. If the server has no database yet, the app creates one for you — the desktop client is no longer needed to get the first one in place.
  4. Sync now — enter your master password to sync once. To keep it in sync automatically, flip on “Auto-sync in the background” on the main screen: you confirm once with biometrics (or your device PIN), and the password is stored encrypted in the Android Keystore (never in plaintext). After that the app syncs on its own — no password, no fingerprint — at an interval you choose (15, 30 or 60 minutes). Idle checks are cheap: it only runs the full decrypt-and-merge when the file or the server has actually changed.
  5. Share from the app if you are the owner: the Share screen lists members, adds one by username, and removes access again — the same flow as the desktop share command.

Deletions made in Keepass2Android / KeePassDX (recycle bin or permanent) propagate to the server and to your other devices, just like on desktop.

Receive a shared database

If someone shares a database with you, it shows up in your list:

./keepass-deltasync databases
# NAME          ID                                    ...  role=member

Bootstrap a local copy with init-shared:

./keepass-deltasync init-shared shared-vault ~/keepass/shared.kdbx

You choose a new local password for your copy — it does not have to match the owner's. After that, you can sync, edit, and share back like any other vault.

Share a database with another user

# Share 'mypasswords' with user 'alice'
./keepass-deltasync share mypasswords alice

# List members
./keepass-deltasync shares mypasswords

# Remove membership
./keepass-deltasync unshare mypasswords alice
Trust model: when you share a database, the recipient gets full read-write access to all entries. Sharing is asymmetrically encrypted but not "revocable" in a cryptographic sense — see architecture for details.

In Firefox — search and go

The Firefox extension answers one question: which page was that account on again? Type kp in the address bar followed by a search, or press Alt+Shift+K for a popup, and it takes you to the entry's website. Logging in is still KeePassXC-Browser's job — this only gets you to the page so that it can do its work, which is why it never needs to see a password. It receives titles, addresses and group names, and requests no host permissions at all.

It does not need a DeltaSync server: a search never touches the network, because the helper reads your local .kdbx through keepassxc-cli and answers from that alone. If you only want the search and have no interest in syncing, you can run the client purely locally.

Installing the Firefox extension covers both routes — with your existing DeltaSync setup, or standalone with no server — plus registering the native messaging host and what to do when nothing happens.

As an administrator

You will typically be responsible for deploying the server and creating user accounts. The full deployment guide lives in the repo:

  • docs/deployment.md — three concrete deployment recipes
  • docs/threat-model.md — what the server sees, doesn't see, and the trust model
  • server/README.md — server overview

Fastest deployment flow

  1. Upload the server/ code to your web host (Hetzner shared hosting or similar PHP + PostgreSQL).
  2. Create the PostgreSQL database and run the migrations from server/schema/ (sequentially 001 through 007).
  3. Fill out server/.env based on .env.example (DB credentials, log level).
  4. Generate the first admin token via a SQL snippet: 
    ./keepass-deltasync admin token-sql
# copy the output to DBeaver, run it, save 'admin_token' from the result
  5. Create users via the admin CLI: 
    $env:KEEPASS_DELTASYNC_ADMIN_TOKEN = "<token>"   # PowerShell
./keepass-deltasync admin user-create alice --display-name "Alice Smith"
# Returns an enrollment token for Alice
  6. Send the enrollment token to the user via a secure channel (not email). They use it once in the enroll command and then get a permanent device token stored in their local config.

Day-to-day operations

Admin commands:

./keepass-deltasync admin user-list                 # tabular overview
./keepass-deltasync admin user-enrollment alice     # new enroll token for an extra device
./keepass-deltasync admin user-disable alice        # block login without deleting data
./keepass-deltasync admin user-enable alice
./keepass-deltasync admin user-delete alice --yes   # permanent, CASCADE

Audit log is available via:

./keepass-deltasync log                             # your own activity
# admin /api/v1/admin/log endpoint returns the entire log

Troubleshooting

"keepassxc-cli not found"

The client looks for keepassxc-cli on PATH, or on Windows in C:\Program Files\KeePassXC\. If it lives elsewhere, set an env var:

$env:KEEPASSXC_CLI = "C:\path\to\keepassxc-cli.exe"
# or pass --keepassxc-cli FLAG to each command

"empty password on stdin"

You piped something empty to --password-stdin. Use the interactive prompt instead (drop the flag), or verify your pipe actually delivers content. On Windows, echo "pw" | client ... is tricky — use PowerShell syntax: "pw" | client ....

"server URL not configured"

You haven't run enroll yet, or your config.toml is gone. Find the file:

  • Windows: %APPDATA%\keepass-deltasync\config.toml
  • macOS: ~/Library/Application Support/keepass-deltasync/config.toml
  • Linux: ~/.config/keepass-deltasync/config.toml

The daemon spams "Fetching..." in logs

Shouldn't happen — the daemon runs in quiet mode. If it does, you probably have an old binary — rebuild from HEAD.
