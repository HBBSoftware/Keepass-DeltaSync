DeltaSync for Edge and Chrome

Type kp in the address bar, a space, then a few letters of the account you are looking for, and the browser takes you to that entry's website. That is the whole extension. It answers the question a password manager leaves you with — which site was that account on again? — and then gets out of the way.

Logging in is not its job. That stays with KeePassXC-Browser, which fills credentials but cannot help you find the page in the first place. This closes that gap and nothing else, which is why it never needs to see a password.

What it can see: entry titles, their web addresses, and group names. Nothing else — the list is enforced on the other side of the connection, in the program that reads your database, so a bug in the extension cannot widen it. The extension also requests no host permissions, so it cannot read the pages you visit. The privacy page has the details.

It is the same extension as the Firefox one, built from the same source files. Only the packaging differs.

You do not need a DeltaSync server

DeltaSync is normally a sync system with a server behind it, but a search never touches the network: the extension asks a small local helper, which reads your own .kdbx file and answers from that alone. So there are two ways to set this up, and the second one has nothing to do with syncing:

  • You already use DeltaSync — your database is registered with the client, and there is nothing extra to configure. Skip to step 2.
  • You just want the search — install the client, point it at your .kdbx with one command, and never enroll against a server at all. That is step 1 below.

What you need

  • KeePassXC, for its keepassxc-cli — that is what actually opens your database
  • The keepass-deltasync client, version 1.9.0 or newer: a pre-built binary for Linux, macOS or Windows, or the Windows installer, which brings it along. Older clients only know Firefox.
  • Microsoft Edge or Google Chrome, version 116 or newer

Step 1 — point the client at your database

If you already sync with DeltaSync, this is done: enroll and init registered the database when you set the client up. Move on to step 2.

If you have no server, the client still needs to know which file to search. One command tells it, and nothing about that file goes anywhere:

keepass-deltasync add-local private ~/keepass/my.kdbx --save-password

private is only a label — it appears in the popup when more than one database is unlocked. Repeat the command for each file you want searchable. No server, no token, no account is involved.

--save-password is optional, but in Edge and Chrome it is worth having. The master password is verified by opening the database before it is kept, and it goes into your operating system's keyring — never into a file. Without it you are asked more often than in Firefox, for a reason explained under Using it.

Windows: where the client is, and where to type

The installer puts the app and the command-line client in the same folder, and which folder depends on the install you chose:

  • Just for me — the default, no administrator prompt: %LOCALAPPDATA%\Programs\KeePass Delta-Sync\
  • For all users: C:\Program Files\KeePass Delta-Sync\

keepass-deltasync.exe in that folder is what every command on this page means. It is not on your PATH, so the quickest way to a terminal that can see it is to open the folder in Explorer, click the address bar, type powershell and press Enter. The terminal opens in that folder, and the commands work with .\ in front:

.\keepass-deltasync.exe add-local private C:\Users\you\Documents\my.kdbx --save-password

Step 2 — let the browser talk to the client

A browser will not run a program unless it has been told about it first. One command does that:

keepass-deltasync install-browser-host

It writes a small manifest for every browser it finds — Edge, Chrome and Firefox alike — into your own user profile, and on Windows a registry key under HKCU. No administrator is needed. Add --dry-run first if you would like to see exactly what it would write. Run it again if you ever move the binary, since the manifest records where it lives.

Read what it prints: it lists every browser it registered with, and that list is the answer to whether it found yours. In the desktop app, the Register with Firefox button runs this same command, so it registers Edge and Chrome too.

The manifest names the extensions allowed to connect, and the client already knows the one from Edge Add-ons. Nothing to copy, no ID to look up.

macOS: clear the quarantine flag

macOS marks anything downloaded with a browser, and the browser starts the helper without a dialog you could approve — so a marked binary dies silently. Clear it once:

xattr -d com.apple.quarantine /usr/local/bin/keepass-deltasync

Linux: snap and flatpak browsers are not covered

A Chromium or Chrome installed as a snap or a flatpak runs in a sandbox that needs special handling, and none of it has been tried. A browser from your distribution's packages or from the vendor's own .deb or .rpm works.

Step 3 — install the extension

Microsoft Edge

It is on Microsoft's own add-on store, signed and reviewed:

Get DeltaSync — KeePass search & go

It asks for two permissions: native messaging, which is how it reaches the client from step 2, and storage, which holds the search index for as long as the browser is open. It requests no host permissions and runs no content scripts, so it cannot see the pages you visit — and it never receives a password from your database.

Restart Edge after step 2 if you have not already, and make sure it really closes. Edge's Startup boost keeps it running in the background after the last window is gone; turn it off under edge://settings/system if a restart does not seem to take.

Chrome, Brave, Vivaldi and Opera

The extension is not in the Chrome Web Store yet. Until it is, install it from source, as below. The client registers itself with all four browsers, but only Chrome and Edge have actually been tested.

From source

The package is plain files with no build step, and the zip published on the releases page is byte-reproducible from its tag — so you can check that what you install is what the source says. To load it:

  1. From a clone, run ./package.sh --dev in extension-chromium/. It builds the extension into extension-chromium/build/unpacked/.
  2. Open chrome://extensions (or edge://extensions) and turn on Developer mode.
  3. Load unpacked, and pick the build/unpacked folder.
  4. Tell the client about this copy — it carries a different ID from the store version, and the client does not trust it on its own: 
    keepass-deltasync install-browser-host --extension-id iocbdcgjepgmakdgfnhlanbncnfmgeof
  5. Restart the browser.

The store version and a source build have different IDs, so both can be installed at once.

Using it

  • Address bar: type kp, a space, then your search. Pick a suggestion and press Enter.
  • Popup: the toolbar button, or Alt+Shift+K. Arrow keys move, Enter opens in the current tab, Ctrl/Cmd+Enter or middle-click opens a new one. New extensions start hidden under the puzzle-piece icon; pin it there to keep the button in view.
  • Lock: drops the cached index and tells the helper to wipe anything it is holding.

Searching matches on host name, title and group, and ranks host names highest — that is usually what you remember. An entry with several addresses (KeePassXC's Additional URLs) shows as one row with a badge; select it and every address unfolds beneath, best match first, so none of them is out of reach.

The first search after a restart needs your master password. If your database is in the OS keyring — which is what --save-password in step 1 arranges — the helper takes it from there itself, and it never passes through the browser. If it is not, the popup asks, and the helper keeps it in memory only.

This is where Edge and Chrome differ from Firefox. They shut an extension's background worker down when it has been idle for a little while, and the helper ends with it, taking a typed password along. The search index survives, so searching still answers at once — but the next time the index is refreshed, the database has to be opened again. From the keyring that takes a few seconds and asks nothing. Without it, the popup asks again.

If something does not work

The popup says it cannot reach the host

The browser reads native messaging manifests at startup, so it has to be restarted after install-browser-host — a new window is not enough, the whole application must close. On Windows that includes Edge's Startup boost and Chrome's Continue running background apps: with either on, closing every window leaves the browser running.

If a restart does not do it, check the client's version with keepass-deltasync version. Anything older than 1.9.0 does not know Edge or Chrome, and registers only Firefox.

It worked, then stopped

The manifest records the full path to the client binary. If you moved, renamed or reinstalled it, run keepass-deltasync install-browser-host again.

The version from source cannot connect, but the store version can

The client trusts the store's ID by itself, and a source build's only when asked. Run install-browser-host with --extension-id as in From source. If you loaded the folder without --dev, the browser made up an ID of its own; it is shown on the extension's card in chrome://extensions.

Is it the browser or is it my setup?

You can exercise the whole chain without the browser involved. This builds the index exactly as a search would and prints what the extension would receive:

keepass-deltasync browser-host --probe private
# No keyring entry for private — the extension would prompt here.
# Masterpassword for private:
# [ { "title": "Example account", "urls": ["https://example.com/login"], … } ]
# 1 searchable entries indexed from private.

If that works and the extension does not, the problem is between the browser and the helper — start with a restart. If it does not work either, the problem is the database binding or keepassxc-cli.

“keepassxc-cli not found”

The helper looks in the usual places for your platform. If yours lives somewhere unusual, confirm that is the problem by pointing at it directly:

keepass-deltasync browser-host --probe private --keepassxc-cli "/path/to/keepassxc-cli"

To make it stick, add the same flag to the launcher that install-browser-host created — it prints the path to it, and to the manifest, every time you run it.

The popup says no databases are registered

Then the helper is running and answering — steps 2 and 3 are fine — and step 1 has not happened yet. Run keepass-deltasync add-local, or press Register database… in the desktop app. keepass-deltasync databases lists what is registered; a search-only database is marked L.

The design and its security boundaries are written up in docs/browser-extension.md. If you also want the syncing half of DeltaSync, start on the getting started page.
