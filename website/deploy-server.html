Deploy your own server

This is the complete, hold-your-hand guide to running your own DeltaSync server. No prior server experience is assumed. You will upload some files, open a page in your browser, click through three short steps, and create your first user. Set aside about 30 minutes.

Good news up front: there is nothing to compile and no Composer / npm step. The server is plain PHP — you upload it as-is. And remember: the server only ever stores encrypted blobs. Even you, the administrator, can never read anyone's passwords.
Have Docker or a NAS? The easiest way is Docker — just below. It takes a few minutes and skips the upload and the setup wizard entirely. The long step-by-step guide further down is for classic PHP hosting without Docker.

The easiest way: Docker

If you have Docker — on a VPS, a home server, or a NAS such as TrueNAS SCALE, Unraid or Synology — this is by far the quickest path. You don't upload any code or run the setup wizard: you paste a few lines of YAML, set one password, and start it. PostgreSQL is included, and the database tables are created automatically on first start.

Use this compose.yml. It pulls a prebuilt, multi-architecture image (works on both x86 and ARM, so Raspberry-Pi-class NAS boxes are fine too):

x-db-password: &db_password "CHANGE_THIS_to_a_long_random_string"

services:
  db:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_DB: keepass_deltasync
      POSTGRES_USER: deltasync
      POSTGRES_PASSWORD: *db_password
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U deltasync -d keepass_deltasync"]
      interval: 5s
      timeout: 5s
      retries: 10

  app:
    image: registry.gitlab.com/star95/keepass-deltasync/server:latest
    restart: unless-stopped
    depends_on:
      db:
        condition: service_healthy
    ports:
      - "8080:80"
    environment:
      DATABASE_URL: "pgsql:host=db;port=5432;dbname=keepass_deltasync"
      DATABASE_USER: deltasync
      DATABASE_PASSWORD: *db_password
      LOG_LEVEL: INFO
      ADMIN_USERNAME: admin
      ADMIN_PASSWORD: "CHANGE_THIS_to_a_long_admin_passphrase"
      PGHOST: db
      PGPORT: "5432"
      PGDATABASE: keepass_deltasync
      PGUSER: deltasync
      PGPASSWORD: *db_password

volumes:
  pgdata:
  1. Change the two secrets. Replace both lines marked CHANGE_THIS. The first is the database password; a YAML anchor feeds that one value to every service, so you only edit it once. The second is the password you will sign in to the admin panel with — at least 12 characters, stored Argon2id-hashed, never in plaintext.
  2. Start it. On a server: save the file and run docker compose up -d. On a NAS, paste the YAML into the app UI instead — on TrueNAS SCALE: Apps → Discover Apps → Custom App → Install via YAML. TrueNAS is fussier than plain Docker about volumes and about what a password may contain, so paste the TrueNAS-shaped compose file there instead of the one above.
  3. Sign in to the admin panel. Open http://<host>:8080/admin.html and sign in with the username and password you set in step 1. Forgotten them later? They are in your compose file.
  4. Create your first user. Type a username under Users and click Create. You get a one-time enrollment token, shown as text and as a QR code. On a phone the user scans the QR code; on a desktop they run keepass-deltasync enroll --server https://your-domain <token> and then follow Getting started. The panel's Next steps tab spells that out, so the token is not all you hand over.

The server now answers on http://<host>:8080. Before exposing it to the internet, put it behind an HTTPS reverse proxy — your NAS's built-in reverse proxy, or Caddy/Traefik/nginx. Updating later is just docker compose pull && docker compose up -d; schema migrations run automatically.

The panel has two more tabs: Devices lists the devices that have enrolled and when each one last called the server, and Audit log shows what happened, with a cleanup button for old rows.

Prefer the command line? The bundled tool does the same work inside the container. docker compose exec app php bin/admin user:create alice creates a user and prints an enrollment token, and docker compose exec app php bin/admin database:create alice Personal creates a database for someone who has no desktop client to create one with.

More detail: the Docker self-hosting guide covers TrueNAS specifics, HTTPS, updating and backups.

Without Docker: classic PHP hosting

No Docker? The rest of this page is the full, beginner-friendly guide to running the server on ordinary shared PHP hosting.

What you need

Before you start, make sure you have all five of these. If you are missing one, sort it out first — the guide assumes they are ready.

  • Web hosting with PHP 8.2 or newer. Almost any shared hosting works (Hetzner, one.com, Simply.com, your own VPS…). It must have these PHP extensions enabled: pdo_pgsql, sodium, and json. The first two are the ones to double-check — ask your host or look in your control panel's PHP settings if unsure.
  • An empty PostgreSQL 14+ database plus a database user that can write to it. Many hosts let you create this in their control panel with a couple of clicks. You do not create any tables yourself — the wizard does that.
  • A domain or sub-domain for the server, e.g. deltasync.example.com, where you can decide which folder it serves files from (the "document root" / "web root").
  • HTTPS on that domain. Almost every host offers a free certificate (Let's Encrypt) with one click. DeltaSync sends authentication tokens, so plain http:// is not acceptable in real use.
  • A way to upload files to your host: a graphical FTP/SFTP program such as FileZilla, your host's web-based file manager, or scp/rsync if you are comfortable with a terminal. Any of them is fine.

The big picture

You will do three things, in order:

  1. Put the code on your host and point your domain at the right folder.
  2. Run the setup wizard in your browser — it asks for your database details, builds all the tables, and gives you an admin token.
  3. Create your first user and hand them an invitation (an "enrollment token").

Step by step

  1. Download the server code. Get the project from GitLab. If you have git: 
    git clone https://gitlab.com/Star95/keepass-deltasync.git
    Or download it as a ZIP from the project page ("Code" → "Download source code") and unzip it. Everything you need is in the server/ sub-folder — you can ignore the rest for now.
  2. Create an empty PostgreSQL database. In your host's control panel, create a new PostgreSQL database (for example named keepass_deltasync) and a database user with a strong password and full access to it. Write down these four things — you will type them into the wizard in a minute:
    • the host (often localhost on shared hosting)
    • the port (PostgreSQL's default is 5432)
    • the database name
    • the user and its password
    Leave the database completely empty — no tables. That is the wizard's job.
  3. Upload the server/ folder to your host. Using FileZilla, your file manager, or scp/rsync, copy the entire server/ folder up to your account — for example to ~/deltasync/server/. Upload all of it: public/, src/, schema/, bootstrap.php, and so on.
    The single most important thing in this whole guide: your domain's document root must point at the server/public/ folder — not at server/ itself. Everything outside public/ (your database password, the source code) must stay above the web root so it can never be downloaded.
  4. Point your domain at server/public/. In your host's control panel, set the document root (sometimes called "web root" or "directory") for your domain to the public/ folder you just uploaded — e.g. ~/deltasync/server/public. Make sure HTTPS is turned on for the domain. On Apache hosting (the most common kind), the included .htaccess file handles the rest automatically; you don't need to touch it.
  5. Open the setup wizard in your browser. Go to: 
    https://your-domain/setup.php
    You should see a page titled "DeltaSync — First-time setup". Prefer Danish? Click Dansk in the corner, or add ?lang=da to the address. If you instead get an error or a blank page, jump to Troubleshooting below.
  6. Wizard — Step 1: Database connection. Fill in the form with the database details from step 2. The "DSN" field is just a single line describing where the database is; use this shape (swap in your own host, port and database name): 
    pgsql:host=localhost;port=5432;dbname=keepass_deltasync
    Then enter the database user and password. You can leave Log level on INFO, Audit retention on 30, and Enrollment token TTL on 24. Leave App base path empty (you only need it for the advanced sub-path setup at the bottom of this page). Click "Test connection and save .env". The wizard tests the connection and, if it works, writes the settings into server/.env for you. If it reports a connection error, your database details are off — re-check the host, port, name, user and password.
  7. Wizard — Step 2: Run the migrations. The wizard now lists the SQL files that build the tables. Just click "Run all migrations". This creates everything the server needs (users, devices, entries, audit log, …). It is safe to run; if the tables already existed it would simply stop and tell you.
  8. Wizard — Step 3: Generate your admin token. Click "Generate admin token". The wizard shows you a long secret string.
    Copy this token now and keep it somewhere safe (your own password manager is ideal). It is shown only once and cannot be retrieved later. This token is what lets you create users.
  9. Delete setup.php. Back in FileZilla / your file manager, delete the file setup.php from the public/ folder on your host. The wizard refuses to run a second time once a token exists, but the file is unnecessary and removing it keeps your server clean. Your server is now live.
  10. Create your first user. Users (and you) are managed with the small command-line client. Download the pre-built client binary for your computer (Windows / macOS / Linux). Then, in a terminal: 
    # 1. Tell the client your admin token (PowerShell on Windows):
$env:KEEPASS_DELTASYNC_ADMIN_TOKEN = "<the-token-from-step-8>"
#    …or on macOS/Linux:
export KEEPASS_DELTASYNC_ADMIN_TOKEN="<the-token-from-step-8>"

# 2. Create the first user:
keepass-deltasync admin user-create alice --display-name "Alice"
    One-time bootstrap: the very first time, the client doesn't yet know your server's address, so the command above may say "server URL not configured". Fix it by creating a tiny config file with just your server URL, then run the command again:
    • Windows: %APPDATA%\keepass-deltasync\config.toml
    • macOS: ~/Library/Application Support/keepass-deltasync/config.toml
    • Linux: ~/.config/keepass-deltasync/config.toml
    with these two lines: 
    [server]
url = "https://your-domain"
  11. Send the invitation to the user. The command prints an enrollment token for Alice. Send it to her over a secure channel (a private message, not email if you can avoid it). She uses it once: 
    keepass-deltasync enroll --server https://your-domain <her-enrollment-token>
    From here she follows the ordinary Getting started steps to bind and sync her database. Repeat steps 10–11 for every additional user (your config already knows the server URL now, so no more bootstrap needed).

Verify it works

The simplest proof is that step 11 succeeded — a user could enroll. If you want to check the API directly, this returns your own account info when the admin (or any enrolled user) is set up:

curl -H "Authorization: Bearer <a-device-token>" https://your-domain/api/v1/me
# → 200 OK with user + device details

Troubleshooting

The page is blank, or I get a "500" error

Almost always this means the document root is pointing at the wrong folder. It must point at server/public/, not server/. Also confirm your host actually runs PHP 8.2+ on this domain.

"Could not load bootstrap.php"

The public/ folder got separated from the rest of server/. Re-upload so that public/ sits inside the server/ folder, next to src/ and bootstrap.php.

"Cannot write to .env"

During setup, the web server needs permission to create server/.env. Make the server/ folder writable by your web user (e.g. chmod 700 server and ensure it is owned by your account), run the wizard, then you can tighten permissions again afterwards.

The wizard says "Setup already complete"

That's fine — it means an admin token already exists, so the wizard locks itself to avoid creating duplicates. Just delete setup.php (step 9) and carry on.

"Connection failed" in Step 1

Your database details are wrong, or the database isn't reachable. On shared hosting the host is usually localhost. Double-check the database name, user, and password, and that the database actually exists.

Login works locally but tokens are rejected

Some FastCGI setups strip the Authorization header. The included .htaccess re-adds it for Apache. If your host uses nginx, you'll need an equivalent rewrite that preserves Authorization and routes unknown paths to index.php.

"pdo_pgsql" or "sodium" extension missing

Enable the PHP extension in your host's control panel (often a checkbox under "PHP settings" / "Extensions"). On a VPS: install the package, e.g. php-pgsql and php-sodium, then restart PHP.

Advanced: sub-path or sub-domain layouts

The guide above is the standard layout: the server has a sub-domain to itself. If instead you want the API to share a domain with a website (e.g. the website on / and the API under /sync), or to split API and website onto two sub-domains, the repository documents three concrete recipes:

  • docs/deployment.md — Recipe 1 (standard), Recipe 2 (API under a sub-path), Recipe 3 (separate sub-domains)
  • server/README.md — server overview and configuration

The only change for a sub-path is to set App base path (e.g. /sync) in Step 1 of the wizard, and to point each client's server URL at https://your-domain/sync.
