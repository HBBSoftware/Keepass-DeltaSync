# Store submission texts

The free-text fields the two Chromium stores ask for, kept here so the next
submission does not start from a blank page. Same idea as
[`../extension/amo-submission.md`](../extension/amo-submission.md), which is
the Firefox equivalent and worth reading first — several of its lessons cost
something to learn.

Everything here is **English**. Neither listing has another locale.

## Before you upload anything

- **Build the package fresh**, and upload the file that build just wrote:

  ```sh
  ./package.sh
  ```

  Not `--dev`: that one carries a development key in the manifest, which
  belongs in `build/unpacked/` and nowhere near a store. `dist/` is git-ignored
  scratch and can hold a build from an older working tree. That is exactly how
  a wrong 0.2.0 went out on AMO.

- **Check what is inside before you upload.** Two things have gone wrong
  before, one here and one on AMO:

  ```sh
  python -c "import zipfile,json; z=zipfile.ZipFile('../dist/keepass-deltasync-chromium-0.1.0.zip'); \
    m=json.loads(z.read('manifest.json')); print('dev key present:', 'key' in m); \
    print([l for l in z.read('popup.js').decode().splitlines() if 'SETUP_URL =' in l])"
  ```

  The key must be absent and the setup URL must point at the website, not at a
  markdown file.

- **The website page must be live.** The popup's two dead ends link to
  `https://deltasync.org/chrome.html`. A package uploaded before that page is
  uploaded ships a link to a 404. Edge Add-ons also checks every URL in the
  description when the listing is saved, and refuses one that does not answer.

- **Screenshots must not show real entries.** The popup lists titles and
  addresses from whatever database is unlocked. Make a throwaway database for
  the pictures:

  ```sh
  keepassxc-cli db-create -p demo.kdbx
  keepassxc-cli add -u alice --url https://example.org -g -L 16 demo.kdbx "Example site"
  keepass-deltasync add-local demo ./demo.kdbx --save-password
  ```

- **Do not publish yet.** Create the submission, note the extension's ID, and
  put it into `chromiumExtensionIDs` in
  `client/cmd/keepass-deltasync/browser_install.go` first — and release that
  client. A published extension that the client refuses to talk to is a bad
  first impression, and it is the same trap the Firefox extension fell into in
  August when it shipped ahead of the client command it told people to run.

  Recorded so far: **Edge Add-ons** `dpmaneajjlanhipmbgdpdnfljiigdnjo`
  (Store ID `0RDCKFJ7FBFG`). Chrome Web Store: not submitted.

## Description

```
Type kp in the address bar, then a few letters of the account you are looking
for, and your browser opens that entry's website. That is the whole extension.
It answers the question a password manager leaves you with — which site was
that account on again? — and then gets out of the way.

Logging in is not its job. That stays with KeePassXC-Browser, which fills
credentials but cannot help you find the page in the first place. This closes
that gap and nothing else, which is why it never needs to see a password.

WHAT IT CAN SEE

Entry titles, their web addresses, and group names. Nothing else. The list is
enforced on the other side of the connection, in the program that reads your
database, so a bug in the extension cannot widen it. The extension requests no
host permissions and runs no content scripts, so it cannot read the pages you
visit, and it never receives a password.

WHAT YOU NEED

The extension cannot open a KeePass database on its own. It talks over native
messaging to the keepass-deltasync client, which you install separately, and
which opens your local .kdbx file through KeePassXC's command-line tool. No
account and no server are involved in searching — that is the optional, other
half of DeltaSync.

Setup takes two commands and is written up here:
https://deltasync.org/chrome.html

HOW IT SEARCHES

Matching runs on host name, title and group, and ranks host names highest,
because that is usually what you remember. An entry with several addresses
(KeePassXC's Additional URLs) appears once with a badge; select it and every
address unfolds beneath, best match first, so none of them is out of reach.

Alt+Shift+K opens the popup. Lock drops the cached index and tells the client
to wipe anything it is holding.

OPEN SOURCE

GPL-3.0. The package is byte-reproducible from its tag: no build step, nothing
minified, the files inside it are the sources.
https://gitlab.com/Star95/keepass-deltasync
```

## Privacy and data collection

Answer: the extension collects nothing.

- **Does it collect personally identifiable information?** No.
- **Does it collect health, financial or payment information?** No.
- **Does it collect authentication information?** No. The master password
  never reaches the browser: the client reads it from the operating system's
  keyring, opens the database, and returns an index.
- **Is data sold or transferred to third parties?** No. Nothing is sent
  anywhere. The extension's only outbound channel is a native messaging port
  to a program on the same machine.
- **Where does what it reads live?** In `storage.session`, which is memory
  only and is dropped when the browser closes.
- **Privacy policy URL:**
  `https://deltasync.org/privacy.html`

## Permission justification

Edge asks for this under certification notes; Chrome has a field per
permission.

```
nativeMessaging — the extension has no way to read a KeePass database itself.
It connects to dk.hbb.keepass_deltasync, a subcommand of the separately
installed keepass-deltasync binary (GPL-3.0, same repository). That program
opens the local .kdbx through keepassxc-cli and returns uuid, title, URLs and
group path — an explicit allow-list enforced in the host. No passwords,
usernames, notes or attachments reach the browser.

storage — session storage only, for the entry index, so that typing in the
address bar does not re-open the database on every keystroke. It is cleared
when the browser closes. Nothing is written to disk by the extension.

No host permissions are requested and no content scripts are declared, so the
extension cannot read or alter any web page. Opening an entry's site is a
tabs.create or tabs.update call with a URL that came out of the user's own
database, and non-navigable values (KeePass {REF:…} placeholders, cmd:// and
other non-http schemes) are filtered out before that call.
```

## Notes to certification

Edge puts this on the final *Submit* page, under a 2,000-character limit that
counts line breaks, and the page has no save button: the text is only kept
when you press Publish. Paste it from here. Say **Yes** to "does a tester need
credentials or other info" — not credentials, but the client.

The client named in step 2 must already be released, and must carry this
store's ID. Otherwise the reviewer gets "cannot reach the host" and rejects it.

```
WHAT IT DOES
A search box over the titles and URLs in the user's own local KeePass database, with navigation to the entry's website. The Chromium build of "DeltaSync — KeePass search & go" on addons.mozilla.org; same source files.

NO ACCOUNT OR SERVER NEEDED
No test credentials exist. The extension talks only to a separately installed local program over native messaging. No account, server or network.

HOW TO TEST (Windows, about 5 minutes)
1. Install KeePassXC: https://keepassxc.org/download/
2. Download keepass-deltasync 1.9.0 or newer (Windows binary): https://gitlab.com/Star95/keepass-deltasync/-/releases
3. In PowerShell, in the folder with the binary, create a demo database and register it. Pick any password when asked, and reuse it:
& "C:\Program Files\KeePassXC\keepassxc-cli.exe" db-create -p demo.kdbx
& "C:\Program Files\KeePassXC\keepassxc-cli.exe" add -u alice --url https://example.org -g -L 16 demo.kdbx "Example site"
.\keepass-deltasync.exe add-local demo .\demo.kdbx --save-password
4. Register the native messaging host (the client already knows this extension's ID):
.\keepass-deltasync.exe install-browser-host
5. Fully close and restart Edge.
6. Open the popup (toolbar button or Alt+Shift+K), type "exa", press Enter: example.org opens. Or type "kp exa" in the address bar.

WITHOUT THE CLIENT
The popup says it cannot reach the host and links to https://deltasync.org/chrome.html. That is intended.

CHECK WITHOUT A BROWSER
.\keepass-deltasync.exe browser-host --probe demo
prints exactly what the extension receives: uuid, title, URLs, group path. Never passwords or usernames.

PERMISSIONS
nativeMessaging: the only channel, to the local program. storage: session storage for the entry index, cleared when the browser closes. No host permissions, content scripts or remote code.

Source (GPL-3.0): https://gitlab.com/Star95/keepass-deltasync
```

## Where each store asks for what

**Microsoft Edge Add-ons** — Partner Center, the Microsoft Edge workspace.
Upload the package, then fill in Availability, Properties and the Store
listing. Certification takes up to seven business days, and the extension's ID
is on the extension's overview page as soon as the submission exists.

**Chrome Web Store** — the developer dashboard. A one-off registration fee,
and a new publisher may have two published items before asking for more. The
item ID appears in the dashboard URL right after the first upload.

Both stores sign the package themselves. The unsigned-zip wording on the
GitLab release applies only to that copy.
